# Leveling history

The site reads the commit history of `roster.csv` from the public GitHub API when it opens, and when someone clicks **Refresh history**. Each version is matched by normalized character name. It starts with the bundled `leveling-history.json` so existing history is available even if GitHub is temporarily unavailable or limits requests. No GitHub token is needed. A failed refresh keeps the bundled data and displays its status.

**Est. XP/hour** assumes each character started at level 1 (0 XP) when Forever released: **November 4, 2026 at 23:00 UTC / 3 p.m. PST / 5 p.m. Central**, as listed in [Blizzard's launch announcement](https://us.forums.blizzard.com/en/wow/t/world-of-warcraft-forever-launch-time/2400905). It divides the XP threshold of the latest recorded level by calendar hours since that release time. The model includes the time and estimated XP before the first saved roster. Later-created characters share this assumed starting point; it does not claim to know their actual creation time.

Each character's **Leveling** tab separately shows **Release → first snapshot**: the XP threshold of its first recorded level divided by the hours from release to that snapshot. The history table displays an explicitly assumed level-1 release row followed by the real GitHub snapshots. The assumed row does not change the count of recorded snapshots and is never written into the original CSV or the recorded history file. The CSV report includes the release baseline, first-interval hours and XP/hour, overall XP/hour, and the latest interval between real snapshots.

XP per level is the LevelExperience table from Forever build 1.60.1.70862, extracted by [Zephras](https://zephras.com/forever/enUS/experience/). The numeric costs are stored in `xp.mjs`, summed from level 1 (0 XP) through level 60 (4,084,700 XP). The calculation uses level milestones; partial-level XP is unavailable. A zero gain in the latest recorded interval is not proof that no XP was earned. Rates for levels outside the supported table are left blank.

The median follows the active roster filters, then keeps only characters at levels 7–59 who were seen online less than 24 hours before the latest export, have a recorded level increase between their latest two observations, and have a positive finite XP/hour estimate. This excludes low-level characters, capped characters, inactive characters, missing estimates, and characters with no recent recorded progression. Activity is an observable proxy; the CSV cannot identify partial-level progress or prove a character is abandoned. The median uses each included character's overall rate since release, not their recent-interval rate. The assumed release point does not count as evidence of recent leveling, so a character with just one real snapshot remains excluded from the active median. For an even sample it averages the middle two values, and the page shows the sample size.

These are estimates over calendar time. GitHub commit times approximate roster capture times; delayed uploads affect the result. Rates include offline time and cannot measure XP per hour played. One real observation can produce a release-based estimate because the level-1 starting point is explicitly assumed. Missing snapshots do not imply a level change, and renames are not inferred. A decrease in level or a change in class suppresses the rate for review. Pre-release timestamps are rejected, and a zero-length interval produces no rate. Local imports have no GitHub upload time, so their rates are left blank.

## Race data

`races.json` is a separate snapshot of the [Phoenix RP US RP guild armory](https://armorywowforever.com/g/forever/us/rp/phoenix-rp). The site uses it only when the name and class match a roster entry. An explicit Race column in the CSV takes precedence. Armory levels never replace CSV levels or enter the leveling history. This keeps the usual five-column guild exports usable. New unmatched characters stay marked Not provided until race data is added. The displayed source date is the retrieval time, not a claim that the armory was freshly scanned then. Update `races.json` from the guild page to refresh the race snapshot.

The level chart adapts to the available width, keeps every level through the highest roster level, and uses fewer numbered ticks on small screens. Each column still has its own tooltip and filter action.

Run `node --test data.test.mjs` to check rate calculations, missing observations, CSV output, future history updates and the existing roster parser.
